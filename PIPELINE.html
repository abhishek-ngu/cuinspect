From CUDA source code to ELF binary inspection — every stage of the compilation and analysis pipeline explained in detail

1. High-Level Pipeline Overview

What This Document Covers

The cuinspect pipeline has three distinct layers. Understanding all three is essential to explain the project end-to-end:

Layer A — CUDA Compilation Pipeline

.cu → PTX → SASS → ELF Binary (.cubin). This is what your tool inspects. You don't build this — you analyze its output.

Layer B — cuinspect Internal Pipeline

File load → ELF parse → Section enumeration → PTX/SASS/DWARF extraction → Occupancy calc → Output. This is what you built.

Layer C — Build & Deploy Pipeline

CMake → LLVM linking → Binary → GitHub Pages showcase. This is how you deliver the project.

Step 1 — Load File into Memory

if (std::error_code EC = BufferOrErr.getError()) {

Step 2 — Parse as ELF Object File

cpp
auto ObjOrErr = ObjectFile::createELFObjectFile(BufferOrErr.get()->getMemBufferRef());
if (!ObjOrErr) {
    llvm::errs() << "Not a valid ELF: " << toString(ObjOrErr.takeError()) << "\n";
    return 1;
}
ELFObjectFileBase* ELF = dyn_cast<ELFObjectFileBase>(ObjOrErr.get().get());

Step 3 — Enumerate All Sections

cpp
for (const SectionRef& Sec : ELF->sections()) {
    StringRef Name; Sec.getName(Name);
    uint64_t Size; Sec.getSize(Size);
    if (Size == 0) continue;
    
    // Print section name + human-readable size
    std::cout << "  " << Name.str() << " " << formatSize(Size) << "\n";
    
    // Capture PTX content for later analysis
    if (Name == ".nv.ptx") {
        StringRef Data; Sec.getContents(Data);
        ptxContent = Data.str();
    }
}

Step 4 — Extract PTX Metadata (Registers, Kernels, Shared Memory)

cpp
// Find .reg .b32 %r; declarations → max register index
std::regex reg32(R"(\.reg\s+\.b32\s+%r<(\d+)>)");
while (std::regex_search(ptx, match, reg32)) {
    maxReg = std::max(maxReg, std::stoi(match[1].str()));
}

// Find .entry kernel_name( → kernel entry points
std::regex entry(R"(\.entry\s+(\w+)\s*\()");

// Find .shared .b8 _name[size]; → shared memory bytes
std::regex shared(R"(\.shared\s+\.b8\s+\w+\[(\d+)\])");

Step 5 — Detect Compute Capability from .nv.info

cpp
int cc = 90;  // default to Hopper
for (const SectionRef& Sec : ELF->sections()) {
    StringRef Name; Sec.getName(Name);
    if (Name == ".nv.info") {
        StringRef Data; Sec.getContents(Data);
        std::regex smRx(R"(sm_(\d+))");
        std::smatch m;
        if (std::regex_search(Data.str(), m, smRx)) {
            cc = std::stoi(m[1].str());
        }
    }
}

Step 6 — Calculate Theoretical Occupancy

Formula

For each resource (warps, registers, shared memory, block count), compute the maximum number of blocks that fit. The limiting resource determines achieved blocks:

maxBlocksByWarps   = maxWarps   / warpsPerBlock
maxBlocksByRegs    = maxRegs    / (regsPerThread * blockSize)
maxBlocksByShared  = maxSharedKB*1024 / sharedMemPerBlock
maxBlocks          = min(all four limits)
achievedWarps      = maxBlocks * warpsPerBlock
occupancy          = achievedWarps / maxWarps * 100%

5. ELF Section Deep Dive — What Each Section Contains

SectionFormatPurposecuinspect Extracts
.nv.ptxTextEmbedded PTX source (for JIT compilation)Kernel names, register declarations (.reg), shared memory (.shared), target arch
.nv.sassBinaryCompiled SASS microcode (GPU executable)Section size; can be piped to nvdisasm for instruction analysis
.nv.infoText/BinaryMetadata: target arch, PTX version, compiler versionCompute capability (sm_XX) via regex parse
.nv.relocBinaryRelocation entries for device code linkingSymbol references, relocation types (R_NV_ABS64, etc.)
.debug_infoDWARFDWARF v5 debug information entriesVariable names, types, locations, NVPTX-specific ops
.debug_abbrevDWARFDWARF abbreviation tableParsed implicitly by DWARFContext
.debug_lineDWARFSource line ↔ PC address mappingSection size reported; line table available via LLVM
.textBinaryHost-side executable codeReported as section size only
.rodataBinaryRead-only constantsReported as section size only
Key insight: CUDA binaries are standard ELF files. The .nv.* sections are NVIDIA-specific custom sections embedded within the ELF container. Standard tools like readelf can see them, but cuinspect goes further by parsing their contents.

6. Usage Pipeline — End-to-End Example

Complete workflow from source to analysis report

Write .cu
__global__ void kernel()
→
nvcc -cubin -g
test.cubin (ELF)
→
./cuinspect
Parse ELF sections
→
Analyze Output
Registers, occupancy, DWARF vars
bash
# Step 1: Write the kernel
cat > test.cu < < 'EOF'
__global__ void matrix_mul(float* A, float* B, float* C, int N) {
    int row = blockIdx.y * blockDim.y + threadIdx.y;
    int col = blockIdx.x * blockDim.x + threadIdx.x;
    if (row < N && col < N) {
        float sum = 0;
        for (int k = 0; k < N; ++k) sum += A[row*N+k] * B[k*N+col];
        C[row*N+col] = sum;
    }
}
EOF

# Step 2: Compile to CUBIN with debug info
nvcc -cubin -arch=sm_90 -g -o test.cubin test.cu

# Step 3: Inspect with cuinspect
./cuinspect test.cubin

# Step 4: Interpret the report
# - Registers: 32/thread → check against SM limit (65536)
# - Occupancy: 75% → limited by registers, consider reducing
# - DWARF vars: uniform vs divergent → warp-level optimization hints
